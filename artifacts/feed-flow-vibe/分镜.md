# 知光 Feed 流：正式分镜（A 透明分拣线）

规格：75 秒｜1920×1080｜30fps｜120 BPM｜无旁白｜代码合成配乐  
核心结论：索引决定看什么，缓存决定从哪里拿，投影决定变化如何到达。

## 镜头 1｜0.0–3.5s

画面：雾白工程纸上，一张占画面近半的 Feed 卡片从左侧推入；屏幕文字“你刷到的，不是一张表。”右侧暂时留白。  
动作：卡片用容器弹簧（w=15,z=0.72）落位；第 4 拍文字逐行压下；3.0 秒橙色切割线沿卡片中缝划过。  
镜头：从 1.05 倍轻拉到 1.0 倍。  
声音：第 1 拍低频 thud；卡片落位 click；3.0 秒纸张切开 whoosh。  
转场：切割线继续向右生长，变成下一镜的三条流水线。  
事实：F02。

## 镜头 2｜3.5–10.0s

画面：卡片被拆成三层透明托盘：`SORT / ZSet`、`CACHE / PAGE + ITEM`、`PROJECT / Outbox`。屏幕文字“三条流水线，同时托住一张卡片”。  
动作：三层依次从卡片内部抽出，每层间隔 1 秒；轨道圆点在重拍滑到末端，使用按钮弹簧（w=24,z=0.8）。  
镜头：跟随最上层轨道向右平移，最后推近 `ZSet`。  
声音：每层落位一个不同音高的 click；7.5 秒三音 ding；9.5 秒短 riser。  
转场：最上层蓝色轨道放大，蓝线变成 ZSet 的排序坐标轴。  
事实：F02、F03、F06、F10。

## 镜头 3｜10.0–16.0s

画面：蓝色排序轨道上只有帖子 ID 方块与 score 数字，没有完整内容；屏幕文字“ZSet 只存 ID + 分数”。  
动作：候选块按 score 自动归位；两个同分块由 postId 决定先后。动作使用按钮弹簧。  
镜头：沿轨道跟随排名从低到高，再停在前 20 个候选。  
声音：排序时连续 type，归位时三次 pop。  
转场：四个候选块向四角分叉，长成四个 API 入口。  
事实：F01、F03。

## 镜头 4｜16.0–22.0s

画面：`HOT / MINE / PROFILE / FOLLOWING` 四条细轨汇入中央 `readPage` 模块；屏幕文字“4 个入口，1 套读页引擎”。  
动作：线路逐条接通；中央模块在 19.5 秒吸入四条线并点亮。  
镜头：固定俯视，19.5 秒短促推近中央模块。  
声音：每条线接通 click；汇合时 thud。  
转场：`readPage` 的出口变成一张带孔的游标票据。  
事实：F01、F02。

## 镜头 5｜22.0–28.0s

画面：游标票据上依次盖章 `kind`、`version`、`score`、`postId`；屏幕文字“游标记住：上次看到哪”。  
动作：四个字段逐个打字出现，票据在 26.5 秒折成 URL-safe Base64 字符串。  
镜头：俯拍特写，票据占画面宽度三分之二。  
声音：盖章 thud ×4；编码完成 ding。  
转场：票据的一角变成书签，插入下一镜的内容流。  
事实：F04、F05。

## 镜头 6｜28.0–33.0s

画面：新卡片不断插到队首，书签仍固定在上次位置；屏幕文字“像书签，不像页码”。  
动作：新卡片从顶部弹入，旧页码被挤乱；书签稳住并指向下一条。  
镜头：固定侧视，主体占画面中央三分之二。  
声音：卡片 pop、书签 click。  
转场：书签横向拉长，变成页面缓存的 ID 清单。  
事实：F04、F05。

## 镜头 7｜33.0–40.0s

画面：左侧页面快照只列 ID 顺序；右侧帖子片段仓按 ID 批量取出内容；屏幕文字“页面存顺序，片段存内容”。  
动作：请求先命中 Caffeine，再落到 Redis Page；缺失片段通过 `MGET` 成批装箱，最后少量回源 MySQL。  
镜头：从左向右跟随一次完整取件。  
声音：L1 命中为轻 click；MGET 为一组 pop；MySQL 回源为低音 thud。  
转场：内容箱盖打开，飞出点赞、收藏和权限三个徽标。  
事实：F06、F07。

## 镜头 8｜40.0–46.0s

画面：共享卡片保持不动，点赞数、收藏数、`liked/favorited` 与可见性徽标在最后一步贴上；屏幕文字“用户状态，最后再补”。  
动作：徽标逐一磁吸到卡片；不符合权限的卡片被筛板挡下。  
镜头：卡片正面特写。  
声音：徽标 click ×4；过滤失败 glitch。  
转场：筛板分成两条物流通道：普通作者与大 V。  
事实：F08。

## 镜头 9｜46.0–55.0s

画面：普通作者将帖子包裹推入多个粉丝 inbox；大 V 像水塔，只保留作者索引，读请求到来时再拉取；屏幕文字“普通作者推，大 V 读时拉”。  
动作：左侧一对多分发；右侧按请求打开阀门；52 秒两路候选合并并去重。  
镜头：先看推送侧，再横移到拉取侧，最后在合流点停下。  
声音：推送侧连续 pop；拉取侧阀门 click；合并 thud。  
转场：合流管道变成一条事件电缆。  
事实：F09。

## 镜头 10｜55.0–62.0s

画面：数据库事务同时写业务数据和 Outbox；电缆依次穿过 `Canal → Kafka → Projector → Redis`；屏幕文字“写数据库，再异步铺路”。  
动作：Outbox 事件被扫描线 Build 成消息，逐站传递；消费者回查数据库后更新索引与片段。  
镜头：跟随消息从左至右移动。  
声音：写入 thud；跨站 whoosh；成功 ack ding。  
转场：消息到达 Redis 后变成热门榜的一颗候选点。  
事实：F10、F11。

## 镜头 11｜62.0–69.0s

画面：候选点落入热度潮汐图；点赞和收藏抬高曲线，时间让曲线缓慢下沉；屏幕文字“互动加分，时间负责退潮”。  
动作：公式拆成三块：`LIKE×3`、`FAV×5`、`TIME^-1.5`，随后合并为榜单；分钟版本号翻页。  
镜头：从公式特写拉远到完整排行榜。  
声音：加分 pop、时间衰减低频滑落、换榜 click。  
转场：排行榜竖线缩成最终手机 Feed 的滚动条。  
事实：F05、F12。

## 镜头 12｜69.0–75.0s

画面：手机 Feed 顺滑追加下一页；背后依次亮起三条线：索引、缓存、投影。屏幕文字“索引定顺序｜缓存提速度｜投影传变化”。  
动作：三条线在 72 秒合成一束知光蓝，托住最终卡片；右下角出现“当前实现 · 源码可核查”。  
镜头：缓慢拉远，留下完整系统轮廓。  
声音：三层依次 ding，结尾短促收束。  
转场：蓝线收成一个光点，定格结束。  
事实：F02、F03、F06、F10、F14。

## 分镜检查

- 每个镜头只解释一个概念；屏幕主句均保留至少 3.5 秒。
- 第一秒直接给出冲突；没有“考你一个问题”式套话。
- 所有转场由线、票据、书签、筛板或管道形变产生，不使用默认淡入淡出。
- 所有具体数字、阈值、TTL 与公式只在其对应事实镜头中出现，并以 `sources.md` 为准。
- 主要文字位于 10%–90% 安全区；最小正文 34px，辅助代码标签不小于 22px。
- 120 BPM 下每 0.5 秒一拍；镜头边界和最大动作均落在整拍。
